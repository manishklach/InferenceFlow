# Owner-encrypted staging evidence

This supports the no-GPU hosted rehearsal only. Real GPU execution and public beta remain disabled.

The proposed export destination is an Actions artifact in `manishklach/InferenceFlow`, named `sealed-staging-evidence-RUN-ATTEMPT`, retained for one day. Because the repository is public, treat the artifact as publicly retrievable. It contains only `evidence.enc.json`: a gzip tar encrypted with a random AES-256-GCM key, wrapped with the owner's RSA-3072 public key using OAEP/SHA256. The version label is authenticated. Randomized encryption, wrong-key rejection and tamper detection are tested. Encryption reduces disclosure risk; it does not make public storage private or eliminate metadata such as file size.

Inside the encrypted payload are synthetic request/results, the read-only audit and the isolated mock PostgreSQL dump. No environment file, Auth0 client secret, metrics/bootstrap bearer, API plaintext key, or database encryption key is included. The dump contains credential hashes and application-encrypted request fields; separate result JSON permits output inspection without exporting application encryption keys. The hosted job initializes a separate, freshly named disposable tenant with one dollar of synthetic test credits through the existing ledger functions. The owner session's zero balance and all customer wallets remain untouched. This is test initialization, not revenue or a payment.

Only the **public** recipient key will be stored as `EVIDENCE_RECIPIENT_PUBLIC_KEY` in protected `staging-experiment` environment variables, after owner approval of this destination. The private key stays under the existing operator/SYSTEM-protected, ignored local staging directory; it is not transferred to GitHub, a Pod, or this repository. The operator must preserve that private key securely. Losing it makes the ciphertext unrecoverable. This setup requires the desktop once to create/store the recipient key; the runner can then seal exports without the desktop online. Owner retrieval/decryption is a separate verification step and must be demonstrated before relying on the mechanism for GPU evidence.

The workflow input `exercise_pipeline=true` performs ten mock requests, verifies API idempotency, waits for all results, checks ten usage and ten unique captures plus reservation release and zero ledger drift, seals the allowed evidence, and shuts down the disposable services. Its successor step uploads only the exact encrypted file, with no directory glob or raw logs. If the pipeline/audit/sealing fails, the upload step does not run. A successful upload alone does not establish a successful decrypt or restore.

After owner approval and a verified upload, download the single encrypted artifact into the ignored private staging directory. Decrypt locally using `scripts.sealed_evidence.unseal` with the operator-held private key; inspect the archive without executing or blindly extracting it. Verify `audit.json` reports mock mode, ten succeeded requests, ten usage/capture records and no errors, and that `database.sql` contains the matching job/ledger data. Record ciphertext/payload hashes and run identity. Keep the raw plaintext private. Account for artifact storage against GitHub's allowance; do not enable overage spending. The target file is small and retained one day, but storage is not assumed universally free.

Approving this mechanism does not authorize a GPU pod, a change to customer billing rates, public plaintext export or a new credential destination.
